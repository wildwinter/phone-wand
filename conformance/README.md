# Conformance suite

These files keep the relay and every client library in step. They are generated by
`bun scripts/conformance.ts` from scripted phone sessions, and checked in CI with
`bun scripts/conformance.ts --check`. Do not edit them by hand.

| File | What it is |
|---|---|
| `sessions/<name>.jsonl` | The input: phone messages and app commands, with timestamps. |
| `app/<name>.jsonl` | The exact messages the relay sends an app for that session, one per line. |
| `app/<name>.events.txt` | The event log a client library must produce from `app/<name>.jsonl`. |
| `app/<name>.state.json` | The player state a client library must hold after the whole stream. |
| `conversions.json` | Rig-frame orientations and the matching Unity, Godot and Unreal values. |
| `index.json` | The protocol version and the list of session names. |

## For relay implementations

Replay `sessions/<name>.jsonl` through the relay with a fake clock and compare the app stream with
`app/<name>.jsonl`, exactly. The first line holds the session's configuration:
`{"config": {"maxPlayers": 4, "key": "k", "smoothing": null}}` (`null` is the relay's default
smoothing, `false` is none). Every later line has a time `t` in milliseconds and one of:

- `open`: a phone connection opens (`"ws"` or `"http"`),
- `close`: it closes,
- `msg`: the phone sends this message,
- `app`: the app sends this message,
- `end`: the session is over.

The relay's once-every-100 ms housekeeping (pausing silent players, removing players whose grace
period has run out) runs at every multiple of 100 ms before any line at or after that time.
Reconnect tokens are `token-1`, `token-2` and so on, in the order players are created. Stats are
not part of the suite, because they depend on real network timing.

## For client libraries

Feed every line of `app/<name>.jsonl` to the client's message handler, as if it came from the relay.
Record one line per event, in the order the events fire:

```
connected protocol=<protocol> max=<maxPlayers>
join <id> slot=<slot> name=<name> colour=<colour>
player <id> state=<state> calibration=<calibration> name=<name> colour=<colour> transport=<transport>
leave <id>
pose <id> seq=<seq> screen=<yes|no>
button <id> <button> <down|up>
control <id> <control>
gesture <id> <gesture> buttons=<held button ids, comma separated, or ->
calibrating <id> <top-left|bottom-right|cancelled>
calibrated <id> <calibration>
stats <id>
```

The log must equal `app/<name>.events.txt` line for line. Notes on when events fire:

- `hello` fires `connected`, then `join` for each player it lists, in order.
- `join` fires `join`; `player` fires `player`; `leave` fires `leave` (only for a known player).
- `pose`, `button`, `calibrating`, `calibrated` and `stats` for an unknown player id fire nothing.
- `button` updates the player's held buttons. A `player` message whose state is not `active` clears
  them.
- `control` for a known player sets that control's value in the player's `controls` and fires
  `control`. A `player` message replaces the player's layout and `controls` entirely.
- `error` (sent when the relay couldn't use something the app sent) fires nothing in the log.
- `calibrating` with `cancelled` clears the player's calibration step; `calibrated` also clears it
  and sets the player's calibration.

After the whole stream, the client's players, in slot order, must match `app/<name>.state.json`:
strings exactly, and numbers to within 0.0001. `buttons` is sorted. `template` is the player's
layout template, and `controls` their control values by id (booleans, numbers or strings). `pose`
is the last pose received for the player, or `null`.

## Frame conversions

Each case in `conversions.json` gives an orientation in the rig frame (`q`, plus the `dir` and `up`
vectors it produces) and the same orientation in Unity, Godot and Unreal terms. A client library's
conversion functions must turn the rig values into the engine values to within 0.0001. Rotating the
engine's own forward (Unity `+z`, Godot `-z`, Unreal `+x`) and up (`+y`, `+y`, `+z`) by the engine
quaternion must give its `dir` and `up`.
